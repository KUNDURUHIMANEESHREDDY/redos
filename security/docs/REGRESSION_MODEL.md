# Regression Model Specification

## Overview

The regression system implements: **Finding → Reproduction Case → Regression Test → Re-execute → Compare → Regression / Fixed**

Every regression test is independent and traceable to its originating finding.

## Regression Test

```python
class RegressionTest:
    test_id: UUID
    name: str
    description: str
    test_type: str = "automated"
    input_data: dict[str, Any]           # Attack payload, endpoint, etc.
    expected_outcome: dict[str, Any]     # {"vulnerability_present": False}
    validation_criteria: list[str]       # Testable criteria
    environment_requirements: dict[str, Any]  # Target, config
    created_from_finding: UUID | None    # Traceability
```

## Test Generation

Generated by `RegressionTestService.generate_test(finding)`:

| Vulnerability Type | Input Payload | Endpoint |
|-------------------|---------------|----------|
| SQL_INJECTION | `' OR '1'='1` | `/api/users` |
| COMMAND_INJECTION | `; cat /etc/passwd` | `/api/exec` |
| XSS | `<script>alert(1)</script>` | `/api/search` |
| PATH_TRAVERSAL | `../../../etc/passwd` | `/api/file` |
| BROKEN_AUTH | `admin'--` | `/api/login` |

## Regression Run

```python
class RegressionRun:
    run_id: UUID
    finding_id: UUID
    test_id: UUID
    execution_id: UUID
    status: str              # pending, running, completed
    started_at: datetime
    completed_at: datetime | None
    result: str              # fixed, regression, error
    details: dict            # Test execution details
    evidence_ids: list[UUID] # Evidence from re-execution
```

## Test Execution Flow

```
RegressionTest
  ↓
RegressionRun created (status=running)
  ↓
Execute test against new execution
  ↓
Validate against criteria
  ↓
Result: "fixed" | "regression" | "error"
  ↓
Run.completed_at = now
Run.result = result
Run.evidence_ids = new evidence
  ↓
Update Finding status:
  - "fixed" → Finding.FIXED
  - "regression" → Finding.REMEDIATED (re-opened)
  - "error" → No status change
```

## Validation Criteria

Per vulnerability type, criteria include:

**SQL Injection:**
- Response does not contain database error messages
- Response does not return unauthorized data
- Query execution time is normal

**Command Injection:**
- Command output not present in response
- Process execution time is normal
- No unexpected files created

**XSS:**
- Payload not reflected unencoded in response
- Content-Security-Policy header present
- Script execution blocked

**Path Traversal:**
- File access restricted to allowed directories
- Path normalization applied
- Access denied for traversal attempts

## Regression Detection

A regression is detected when:
- `result == "regression"` in latest execution
- Finding status transitions: FIXED → REMEDIATED
- Baseline comparison shows risk score delta > threshold

## Evidence Traceability

- Test `created_from_finding` links to originating finding
- Run `evidence_ids` = evidence from re-execution
- Run `details` includes input, expected, actual, validation_passed
- Finding status updated based on run result

## Independent Execution

Regression tests are **independent**:
- Can be executed without finding context
- Test contains all necessary input/validation data
- Can be run in CI/CD pipelines
- Results stored with execution context

## Baseline Integration

Regression feeds baseline system:
- New findings increase baseline metrics
- Fixed findings decrease baseline metrics
- Regression detected → baseline alert

## Anti-Fabrication Guarantees

1. **Test from finding** - Cannot create test without finding
2. **Evidence from execution** - Run evidence comes from real re-execution
3. **Validation criteria** - Must pass explicit checks
4. **Status transitions enforced** - Cannot skip FIXED/REGRESSION_TESTED
5. **Full audit trail** - All runs stored with timestamps
